# Cheeseless: adversarial design review

Reviewed 2026-11-13 against `planning/ledger.md` only; no implementation inspected. The ledger contains Q1–Q34 (Q30/31 combined), **no Q35**, and AC1–AC13. AC numbers below refer to the numbered MVP criteria; the canary rule is additional.

Scope: implementation agent (A), test author (T), orchestrator (O), and candidate runtime (R); full shell inside the stated sandbox, no malicious operator or kernel exploits. These are attack hypotheses, not claims of demonstrated exploits or benchmark-specific incidents. They cover benchmark-style answer leakage, specification gaming, evaluator tampering and reward hacking.

`GAP` means no explicit sufficient control; named decisions followed by “partial” describe intent or incomplete coverage, not a proven mitigation. Severity is potential impact assuming the stated precondition: critical = falsify authoritative PASS/promote or cross the trust boundary; high = expose hidden evaluation or systematically evade it; medium = narrower leakage/overfit/availability; low = bookkeeping. Test ideas are adversarial acceptance tests, not proofs of universal security.

## Top 5 gaps and decisions to change

1. **Trusted execution closure is undefined (V01–V16).** Protecting three path prefixes is insufficient: pytest config, build hooks, dependencies, CI helper scripts and cached artifacts can determine the verdict. Q17/Q21 are **wrong if treated as sufficient integrity controls**. Use immutable trusted runner/tests/dependencies, isolated candidate builds, fail-closed policy and authenticated evidence bound to the exact promoted tree and baseline.
2. **Authority is not closed across agents/tools (L03–L14, S01/S06).** Q12's cooperative hook is **wrong as a confidentiality boundary**, especially given Q30/31. Isolate O/reviewers too; authorize host-side tools by task identity; separate UIDs/namespaces/sockets, mounts, fds, credentials, memories and threads. Q15's domain allowlist alone does not make these capabilities safe.
3. **Same-model test authoring has an unresolved information/quality boundary (T01–T08).** Q2's “fresh delegate” is **wrong as a sufficient reset guarantee**; correlated knowledge persists through tools/artifacts and correlated reasoning survives a context reset. Keep independent requirement/reference evidence, negative controls/mutation checks, public-artifact review, and a genuinely separated implementation identity; Q9 vendor diversity is useful but not proof of strength.
4. **Unlimited adaptive evaluation consumes secrecy (O01–O10).** Q18's unlimited runs are **wrong if intended to resist inference**: criterion bits, timing and CI red/green all provide an oracle. Budget queries across sessions and CI, define error/timing disclosure, and reserve a final evaluation unavailable for iterative probing. Q27's per-node random 25% cannot guarantee independent behavioral coverage, especially for small suites.
5. **PASS is broader than observed evidence (G01–G07, S03–S05).** A black-box finite suite cannot guarantee Q1's absolute “cannot game”; environment-conditioned and memorized implementations can pass. State the measurable assurance boundary, add randomized/metamorphic/sequence and launch-environment checks, and support honest FAIL/blocked. Q19's PASS-only acceptance is **wrong if it means unbounded retries or pressure to waive an impossible task**; accept only trusted PASS for promotion while allowing failure as a valid terminal task outcome.

The single-string canary is a useful regression probe, not a confidentiality proof: a candidate can leak a transformed secret, test structure or answers without ever emitting that string. Expand it to multiple artifact-specific sentinels, partial/encoded leakage checks and adversarial capability tests. Missing Q35 needs reconciliation before this review can claim coverage of Q1–Q35.
