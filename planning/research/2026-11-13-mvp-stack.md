# cheeseless MVP stack verification (2026-11-13)

Env: WSL2 kernel 6.18.58.1-microsoft-standard-WSL2, bubblewrap 0.11.1 (/usr/bin/bwrap), claude 2.1.319, codex-cli 0.165.0, ripgrep present, **socat absent**.

## 1. Anthropic sandbox-runtime (srt)
- Install: `npm install -g @anthropic-ai/sandbox-runtime` (npm latest 0.0.83). Not installed here (per brief).
- Linux backend: bubblewrap + seccomp BPF (prebuilt x64/arm64) + `socat` (proxy bridge) + `ripgrep` (deny-path detection).
  Network namespace is removed entirely; traffic goes through host proxies via bind-mounted unix sockets.
- Config: `~/.srt-settings.json` or `srt --settings <file> <cmd>` (JSON):
  `{"network":{"allowedDomains":[...],"deniedDomains":[...]},"filesystem":{"denyRead":["~/.ssh"],"allowRead":[],"allowWrite":[".","/tmp"],"denyWrite":[".env"]}}`
  - Network: deny-all by default; empty `allowedDomains` = no network. Entries may carry port.
  - Reads: allowed everywhere by default; `denyRead` (globs ok; a glob whose first path component is a wildcard is skipped on Linux), `allowRead` overrides deny.
  - Writes: denied by default; `allowWrite` literal paths only on Linux (globs skipped); `denyWrite` wins.
- **Unix sockets (key)**: blocked on Linux by seccomp (blocks creating AF_UNIX sockets). `allowUnixSockets` path list is
  **ignored on Linux** ("seccomp can't filter by path"). Only escape hatch: `allowAllUnixSockets: true` (disables the seccomp
  filter entirely; then bwrap gets `--disable-userns` instead; any unix socket incl. docker.sock/ssh-agent becomes connectable if the path is visible).
  Source: https://github.com/anthropic-experimental/sandbox-runtime README (lines ~517-523, 717).
- Empirical (this host): plain `bwrap --ro-bind / / --unshare-net ...` can connect() to a host UDS (filesystem socket
  visible through the bind) and has no external network (`Network is unreachable`). So UDS-through-bwrap works; the limit is srt's seccomp layer, not bwrap.
- WSL2: README mentions WSL 2 only for /mnt/c 9p mount handling (line ~1185) and "WSL not covered by Windows sandbox"; no explicit "supported on WSL2 Linux" statement found. Plain bwrap works here (tested). Ubuntu 24.04+ may need `kernel.apparmor_restrict_unprivileged_userns=0`.
- Limitations: needs socat (apt) + rg; Linux write globs unsupported; nested userns blocked by default (no nested bwrap/chromium/podman); x64/arm64 only; alpha-ish version 0.0.x.
- Verdict: **srt cannot do per-path UDS allow on Linux; use either srt with `allowAllUnixSockets:true` (weak) or drive `bwrap` directly (UDS works, tested, full control). socat is not installed here.**

## 2. MCP structuredContent / outputSchema; per-invocation MCP; hooks
- Claude Code: CHANGELOG 2.0.21 "Support MCP structuredContent field in tool responses"; docs page does not specify. **Empirical test (claude 2.1.319, haiku, `--strict-mcp-config`)**:
  server returned `content=[text "TEXTBLOCK-ALPHA"]` + `structuredContent={"k":"STRUCT-BRAVO"}`; the model reported only
  `k: STRUCT-BRAVO`. => structuredContent takes precedence over the text block when both are present (text block not seen).
  Not tested: whether outputSchema is shown to the model (likely only used for validation). Design: put the full criterion-level JSON in structuredContent AND an identical text block.
- Claude per-invocation MCP: `--mcp-config <json file|string>` + `--strict-mcp-config` (docs: strict session uses only servers from `--mcp-config`). Worked in the test above.
- Codex CLI (0.165): `codex-rs/protocol/src/models.rs` (~L2634): if `structured_content` is non-null it is serialized with serde_json and used as the FunctionCallOutput text body, in preference to content blocks. (source: github.com/openai/codex main). Unit tests in same file confirm `{"result":"structured"}`.
- Codex per-invocation MCP: **works**: `codex -c 'mcp_servers.foo.command="echo"' mcp list` showed `foo` enabled (tested). Also `[mcp_servers.<name>]` in config.toml; docs don't mention -c but it is the generic TOML override.
- Codex Stop hook: **yes**. Docs (https://learn.chatgpt.com/docs/hooks, formerly developers.openai.com/codex/hooks): hooks.json or `[hooks]` in config.toml; events incl. `Stop`, `PreToolUse`, `PostToolUse`, `SubagentStop`...; Stop returns `{"decision":"block","reason":...}` to continue the turn. On by default; discovered in `~/.codex/hooks.json`, `<repo>/.codex/hooks.json`; **non-managed hooks must be reviewed/trusted (`/hooks`) and project hooks need trusted project** => for headless runs plan how trust is pre-granted (or use user-level config).
- Verdict: both pass structuredContent; both support per-invocation MCP; Codex Stop hook exists (trust gating is the catch).

## 3. import-linter
- PyPI import-linter **2.16** (2026-11-06), Python >=3.11. Config in `pyproject.toml` under `[tool.importlinter]` (root_package(s)) + `[[tool.importlinter.contracts]]` with `type = "layers" | "forbidden" | "independence"` (also acyclic_siblings, protected, custom). Run `lint-imports`.
- Expressible (module names illustrative):
  - Domain imports nothing internal: `type="forbidden"`, `source_modules=["cheeseless.domain"]`, `forbidden_modules=["cheeseless.app","cheeseless.ports","cheeseless.adapters"]` (also forbid `cheeseless.cli` etc.). Use `allow_indirect_imports` only if needed (default is to catch transitive chains).
  - App only domain+ports: `forbidden` with `source_modules=["cheeseless.app"]`, `forbidden_modules=["cheeseless.adapters", ...]`; plus a `layers` contract `layers = ["cheeseless.adapters","cheeseless.app","cheeseless.ports","cheeseless.domain"]` (higher may import lower only). Note layers alone permits app -> domain/ports but also forbids upward; to forbid app importing anything else (e.g. third-party) use forbidden with `include_external_packages=true` + root_package listing.
  - Adapters independent of each other: `type="independence"`, `modules=["cheeseless.adapters.git","cheeseless.adapters.sandbox", ...]`.
- Caveat: static import analysis only (grimp); dynamic imports invisible. (Contract-type docs page could not be re-fetched here; schema above is from known 2.x docs, run `uvx --from import-linter==2.16 lint-imports` on a stub to confirm before committing.)
- Verdict: yes.

## 4. Protobuf in Python / Connect
- protojson: `google.protobuf.json_format.MessageToJson/ParseDict` in protobuf (PyPI 7.36.2). Fine.
- buf: PyPI `buf` is an unrelated 2018 package (1.0.0), do NOT use. `buf-bin` 1.75.0 on PyPI ("Buf CLI distributed via PyPI", official-looking, bufbuild repo links) is the uv-installable route; otherwise static binary. Alternative with no buf: `grpcio-tools` 1.85.1 (`python -m grpc_tools.protoc`).
- Connect-RPC Python: `connectrpc` 0.13.0 (2026-10-25, Beta, 9 releases; older name `connect-python` 0.9.0 stale). Repo connectrpc/connect-python; WSGI/ASGI server, sync+async clients on `pyqwest` (0.14.0, reqwest wrapper), passes Connect conformance suite. Codegen needs buf + remote plugin (buf.build/connectrpc/py) => network at build time. **UDS: no documentation found for pyqwest/connectrpc clients; treat as unsupported/unverified.** Beta, pre-1.0, extra toolchain.
- Recommendation: skip Connect for MVP. Plain HTTP/JSON over UDS: server stdlib `http.server`/uvicorn `--uds`; client `httpx.Client(transport=httpx.HTTPTransport(uds="/path/v.sock"))` (httpx 0.28.1, supported). Keep wire schema as pydantic/protobuf-JSON (`json_format`) so a later move to Connect (it speaks JSON over HTTP) is non-breaking.
- Verdict: protojson fine; Connect not mature enough; HTTP/JSON over UDS.

## 5. Python MCP SDK
- `mcp` **2.3.0** (2026-10-02, Python >=3.10). **Breaking: 2.x renamed `FastMCP` -> `mcp.server.mcpserver.MCPServer`; `mcp.server.fastmcp` raises ModuleNotFoundError** (hit this in my test). Pin `mcp>=2,<3` and import MCPServer, or pin `mcp<2` for FastMCP.
- Structured output: `@tool(structured_output=True|None)`; return annotations (pydantic/TypedDict/dataclass) generate `outputSchema` and populate `structuredContent` (+ text block); returning `CallToolResult(content=..., structuredContent=...)` is passed through (used in my Claude test). Source: installed mcp 2.3.0 `server/mcpserver/server.py` L627+.
- Verdict: yes.

## Design-affecting blockers
1. srt on Linux ignores `allowUnixSockets` and needs socat (not installed). Agent->verifier UDS requires `allowAllUnixSockets:true` (or run bwrap directly: UDS verified working with --unshare-net). Recommend own thin bwrap wrapper, srt optional.
2. Claude Code shows structuredContent INSTEAD of text block: make them identical/complete; do not hide data in the text block only.
3. mcp 2.x API rename (MCPServer); pin version.
4. Codex hooks require trust approval; plan for headless runs.
