cheeseless: the author side (scripted agents)

# Author side of cheeseless. The agents below are scripted stand-ins, not LLMs.
# The repo has a spec and a smoke test; there are no hidden tests yet.
$ git ls-files
README.md
acceptance/contract/criteria.yaml
acceptance/contract/spec.md
acceptance/contract/test_smoke.py
src/toy/__init__.py
src/toy/__main__.py

# The spec's tie rule, which every hidden test must agree with:
$ grep 'equal length' acceptance/contract/spec.md
- words of equal length keep their input order (a stable sort)

# 1. A reference session sees only the contract (spec + criteria), never tests.
#    It writes a reference implementation from the spec.
$ cheeseless session --role reference --task <placeholder-task> --projection <ref-worktree> -- <scripted agent: reference>
  agent> I can see 5 files: README.md, acceptance/contract/criteria.yaml, acceptance/contract/spec.md, src/toy/__init__.py, src/toy/__main__.py
  agent> test files visible to me: 0
  agent> implementing from the spec: words of equal length keep their input order (a stable sort)
  agent> wrote src/toy/__main__.py
$ cheeseless reference record --worktree <ref-worktree>
reference recorded: <id-1>

#    What the reference prints for a tie (bb and aa have equal length):
$ printf 'bb aa\n' | python3 src/toy/__main__.py score   # in <ref-worktree>
bb
aa

# 2. The author writes hidden tests. One of them is deliberate bait:
#    test_ties_alphabetical contradicts the spec's stable tie rule.
#    author_crosscheck runs the tests against the reference and goes red.
$ cheeseless session --role author --task <placeholder-task> --projection <author-worktree-1> -- <scripted agent: author-bait>
  agent> writing hidden tests, including test_ties_alphabetical (contradicts the spec)
  agent> wrote acceptance/hidden/test_normalize.py
  agent> wrote acceptance/hidden/test_score.py
  agent> tie test test_ties_alphabetical:
  agent>   assert candidate.run(["score"], stdin="bb aa\n").stdout == "aa\nbb\n"
  agent> author_check       -> ok=True, problems=[], tests=4
  agent> author_crosscheck  -> green=False, red_criteria=['score']
  agent> freeze_propose     -> proposal_id=<proposal-1>
$ cheeseless promote --role author --worktree <author-worktree-1>
promoted refs/heads/spec/toy <id-2>
$ git merge --ff-only spec/toy

#    The host tries to approve anyway; the red crosscheck blocks it.
$ cheeseless freeze --approve <proposal-1> --as host
refused: the reference failed the author's tests: score

# 3. The author fixes only the test that contradicted the spec.
#    The crosscheck turns green and the host approves the freeze.
$ cheeseless session --role author --task <placeholder-task> --projection <author-worktree-2> -- <scripted agent: author-fix>
  agent> the crosscheck was red on score; fixing only the test that contradicts the spec
  agent> wrote acceptance/hidden/test_normalize.py
  agent> wrote acceptance/hidden/test_score.py
  agent> tie test test_ties_keep_input_order:
  agent>   assert candidate.run(["score"], stdin="bb aa\n").stdout == "bb\naa\n"
  agent> author_check       -> ok=True, problems=[], tests=4
  agent> author_crosscheck  -> green=True, red_criteria=[]
  agent> freeze_propose     -> proposal_id=<proposal-2>
$ cheeseless promote --role author --worktree <author-worktree-2>
promoted refs/heads/spec/toy <id-3>
$ git merge --ff-only spec/toy

#    Operator decisions need a code retyped on the terminal (ADR 0017).
#    The demo plays the operator on a pty it owns: it reads the code and types it back.
$ cheeseless freeze --approve <proposal-2> --as host
cheeseless: confirm an operator decision at this terminal
  operation: freeze-approve
  lineage:   toy
  subject:   <proposal-2>
  actor:     host
  outcome:   freeze
type this code to confirm: A4Q98FJW
(typed back: A4Q98FJW)

frozen task: <proposal-2>

# 4. After the freeze the author can no longer change the suite.
$ cheeseless session --role author --projection <author-worktree-3> -- <scripted agent: author-late>
  agent> trying to change the frozen suite
  agent> author_check       -> refused: author_refused
  agent> freeze_propose     -> refused: author_refused

# 5. The implementer never sees the hidden tests. It guessed alphabetical ties,
#    fails score, and disputes the criterion. The ack says nothing about tests.
$ cheeseless dispute config --enable
disputes enabled, cap 3
$ cheeseless session --role implementer --projection <impl-worktree> -- <scripted agent: implementer>
  agent> hidden test files visible to me: 0
  agent> wrote src/toy/__main__.py
  agent> run -> fail (normalize=pass, score=fail)
  agent> dispute(score, contradicts_spec) -> Dispute recorded. This session is closed.
$ cheeseless disputes --show-note --json
{
  "disputes": [
    {
      "code": "contradicts_spec",
      "criterion": "score",
      "id": "d-1",
      "lineage": "toy",
      "note_untrusted": "score fails but my output is sorted; I think the tie rule is wrong",
      "resolved_by": "",
      "status": "open",
      "task": "<proposal-2>"
    }
  ]
}

#    The host reads the note, checks the spec and rejects the dispute.
$ cheeseless dispute resolve d-1 --rejected --as host
cheeseless: confirm an operator decision at this terminal
  operation: dispute-resolve
  lineage:   toy
  subject:   d-1
  actor:     host
  outcome:   rejected
type this code to confirm: WCNVA7GW
(typed back: WCNVA7GW)

d-1: rejected by host
A fresh implementer session may start for this task.
